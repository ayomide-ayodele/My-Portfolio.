FinTech Product Case Study

Understanding Everyday Spending in Mobile Banking

A product concept exploring how mobile banking can turn transaction history into lightweight, understandable spending insights.

Explore case study
Focus: FinTech / Financial Awareness Status: Product Concept Scope: Mobile Banking / Spending Insights

Problem Context

Where Mobile Banking Falls Short

Mobile banking adoption has made it easier to send money, pay bills, and manage accounts. Apps such as OPay, PalmPay, Kuda, and Revolut make transactions convenient, but transaction lists primarily provide information rather than interpretation.

Users can see what they spent, but they cannot easily see patterns over time. This creates an opportunity for mobile banking products to move beyond transaction tools toward lightweight financial insight systems.

The deeper problem is not a lack of data. The problem is a lack of meaningful synthesis. Users can become overwhelmed by raw transaction data and may benefit from automated analysis that highlights trends, anomalies, and changes in spending behavior.

Problem Definition

The Spending Awareness Gap

Problem 1

Transaction Lists Are Not Insights

Many mobile banking users frequently check their balance but rarely review their spending history in detail. Transaction lists can be long and difficult to interpret, making it harder to notice recurring expenses, unusual spending, or changes in behavior.

Problem 2

Raw Data Without Context

Financial awareness matters for budgeting and financial stability. Yet many banking experiences prioritize showing transactions rather than helping users understand them. A lightweight insight layer could bridge that gap without overwhelming users.

User Research

What 50+ Conversations Revealed

Exploratory conversations with mobile banking users uncovered recurring patterns in how people interact with their transaction data.

Frequent Balance Checks

Users check their balances several times a day but rarely analyze their transaction history in depth. The balance number provides reassurance, but not understanding.

Mental Estimates

Many users rely on rough mental estimates rather than reviewing actual spending patterns. This leads to surprises when the month doesn't match their internal picture.

Desire for Simplicity

Users expressed interest in simple, automated insights when those insights are presented clearly and without unnecessary complexity. They don't want another dashboard to manage.

These findings are exploratory, based on 50+ conversations, not a statistically representative study.

Product Opportunity

From Visibility to Understanding

Move mobile banking from transaction visibility toward spending understanding.

The product should not attempt to become a full financial-planning or budgeting platform. The opportunity is much narrower: help users notice meaningful changes in their spending without requiring them to manually analyze transaction histories.

This distinction is important. The goal is awareness, not financial advice. The value comes from turning existing transaction data into useful interpretation.

Solution Concept

Spending Insight Layer

A lightweight addition to existing mobile banking apps that transforms transaction data into understandable spending patterns.

The concept would sit quietly in the background and analyze transaction data to surface useful information without requiring users to build budgets or study complicated dashboards.

Potential insight types include weekly and monthly spending summaries, category breakdowns, gentle alerts for unusual spending spikes, and simple behavioral observations. For example: "You spent 20% more on dining this month." The purpose is awareness, not financial advice.

Insights should be optional, non-intrusive, understandable, contextual, and privacy-conscious.

Solution Overview

How the Insight Layer Could Work

Auto-Categorisation

Automatically group spending by merchant and category, while allowing users to correct classifications.

Weekly Summaries

Provide brief summaries of total spending compared with the previous week and highlight meaningful category changes.

Contextual Alerts

Identify recurring subscriptions, unusual spending spikes, or potentially unused services.

Monthly Snapshot

Show income versus spending, major categories, and saving rate, with the option to explore further.

Core Experience

From Data to Awareness

The proposed experience is simple: transaction data flows into pattern detection, which surfaces lightweight insights that build user awareness over time. The product should not require users to open a separate financial dashboard every day. Useful financial awareness should appear naturally within the banking experience.

Design Principles

Guiding the Insight Experience

Minimal Cognitive Load

Insights should be understandable immediately, without requiring analysis or interpretation.

Context Over Complexity

Surface useful information where users already interact with their transactions, rather than forcing them into a complicated dashboard.

Awareness, Not Advice

Help users understand their behavior without telling them what financial decisions they must make.

Optional and Non-Intrusive

Users should be able to dismiss insights or categories they do not care about.

Privacy-Conscious

Financial information is sensitive. The concept should prioritize privacy and responsible handling of transaction data.

Product Thinking

Key Product Trade-offs

Design decisions that balance value with user experience.

Awareness vs. Overload

More insights do not necessarily mean more value. The product should prioritize a small number of meaningful observations rather than presenting users with endless analytics.

Automation vs. User Control

Automated categorization and insight generation reduce effort, but users need the ability to correct or dismiss information.

Personalisation vs. Privacy

More personalized insights require deeper use of financial data. The product must balance useful personalization with responsible data handling.

Engagement vs. Intrusion

The product should encourage meaningful engagement without creating unnecessary notifications or anxiety around spending.

User Scenarios

How the Concept Could Help

Scenario 1

Everyday User

A user checks their banking app regularly but rarely reviews their complete transaction history. The product surfaces a simple weekly spending summary that helps them understand where their money has gone.

Scenario 2

Changing Spending Patterns

A user's dining or transportation spending increases significantly compared with their normal pattern. The system surfaces a contextual observation rather than requiring the user to manually compare transaction histories.

Scenario 3

Subscription Awareness

A user has recurring payments they may have forgotten about. The system identifies the pattern and surfaces it as an optional insight.

Product Positioning

What This Product Is (And Isn't)

Not a budgeting app. Not a financial advisor. Not a complex analytics dashboard. Not a replacement for existing banking functionality.

This concept is a lightweight spending-awareness layer inside mobile banking. Its value comes from turning existing transaction data into useful interpretation.

Potential Impact

Outcomes to Validate

These are potential benefits, not proven results.

  • Improve users' awareness of spending patterns
  • Make transaction history easier to understand
  • Help users notice unwanted subscriptions
  • Encourage more meaningful engagement with their banking app
  • Improve users' sense of financial control

Validation Plan

What Needs to Be Tested

Before building or launching, these questions would need to be explored:

  1. Do users actually understand the insights without explanation?
  2. Which insight types are genuinely useful?
  3. How frequently should insights appear?
  4. Do users trust automated categorization?
  5. How much control do users want over categories and notifications?
  6. Does the feature improve financial awareness without increasing anxiety or cognitive load?
  7. What privacy expectations do users have around transaction analysis?

Reflection

What This Concept Taught Me

The strongest opportunity is not necessarily adding more financial functionality. It is making existing financial data more understandable. The product challenge is therefore one of interpretation, prioritization, and trust rather than simply adding another dashboard.

Next Steps

From Concept to Validation

  1. Prototype – Design the insight experience within an existing mobile banking transaction flow.
  2. Usability Testing – Test whether users understand the insights without additional explanation.
  3. Insight Prioritization – Identify which categories of insight users find most valuable.
  4. Trust and Privacy Validation – Understand users' expectations around financial-data analysis, categorization, personalization, and notifications.
  5. Controlled Experiment – If implemented within a real banking product, test whether the insight layer improves meaningful financial awareness and engagement.
